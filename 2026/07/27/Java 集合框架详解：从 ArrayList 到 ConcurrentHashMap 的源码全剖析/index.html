Java 集合框架（Java Collections Framework, JCF）是 JDK 中最常用、面试提问频率最高的模块之一。从 ArrayList 的动态扩容到 HashMap 的红黑树，从 ConcurrentHashMap 的分段锁到 Java 21 的 SequencedCollection，每一个细节都可能是后端面试的”拦路虎”。本文从集合框架总览出发，逐层拆解 List / Set / Map / Queue 四大接口的经典实现，配套 JDK 源码逐行解读、性能对比、生产避坑与 8 道高频面试题。读完本文，你将真正”看穿”集合框架，而不是只会用 list.add()。

Java 集合框架详解：从 ArrayList 到 ConcurrentHashMap 的源码全剖析

一、为什么集合框架是 Java 后端的”必修课”

1.1 业务中高频到”无处不在”

打开任何一份 Java 后端代码，import java.util.* 几乎都会出现。集合承担了三大职责：

  • 数据暂存：用户列表、订单缓存、消息堆积
  • 算法骨架：排序、查找、去重、统计
  • 并发协作：生产者-消费者、阻塞队列、线程安全容器

如果对集合的实现原理只停留在”会用 API”层面，遇到下面这些场景就会翻车：

场景 错误预期 真实结果
100 万条数据频繁插入删除 用 ArrayList O(n) 的数组拷贝，CPU 飙到 100%
多线程并发写 Map 用 HashMap 死循环（JDK 7）/ 数据丢失（JDK 8+）
需要有序且去重 随手用 HashSet 失去插入顺序，遍历结果不可控
千万级数据统计 TopK 遍历全表 内存溢出 OOM

1.2 面试官最爱的”八连问”

  1. ArrayList 和 LinkedList 有什么区别？底层数据结构是什么？
  2. HashMap 底层是怎么实现的？为什么用红黑树而不是 AVL？
  3. HashMap 是线程安全的吗？多线程下会出什么问题？
  4. ConcurrentHashMap 在 JDK 7 和 JDK 8 的实现有什么不同？
  5. 为什么 ConcurrentHashMap 读操作不需要加锁？
  6. 什么是 fail-fast？什么是 fail-safe？两者区别？
  7. 集合类有哪些线程安全版本？分别适用什么场景？
  8. Java 8 / 17 / 21 集合框架有哪些新特性？

能否流畅回答这些问题，决定了你能否拿到 P6+ 的 offer。

3.2 LinkedList：双向链表的”全才”

3.2.1 底层数据结构

LinkedList 同时实现了 List 和 Deque 接口，既能当列表，又能当双端队列、栈使用。

3.2.2 性能特点

操作 时间复杂度 说明
get(i) O(n) 需要从头/尾遍历
addFirst/addLast O(1) 头尾插入极快
removeFirst/removeLast O(1) 头尾删除极快
add(i, e) 中间插入 O(n) 先遍历到 i，再插入
contains(e) O(n) 遍历 equals

反直觉的事实：

  • 现代 JVM（HotSpot）下，LinkedList 随机访问速度其实不比 ArrayList 慢太多
  • LinkedList 每个节点有 24 字节额外开销（item + prev + next + Object header），内存占用大
  • CPU 缓存命中率低，遍历大列表 ArrayList 通常更快

3.3 怎么选？List 选型决策

生产经验：

  • 99% 场景用 ArrayList 就对了
  • 只有频繁头尾操作（如实现消息队列）才用 LinkedList
  • 追求极致随机访问性能可考虑 TIntArrayList（trove4j）、fastutil

3.4 CopyOnWriteArrayList：读写分离的”写时复制”

适用场景：读多写极少（如配置中心、监听器列表）

不适用：写多场景（每次写都复制数组，内存爆炸）

5.1.4 扩容机制（resize）

扩容优化：JDK 8 后，节点 rehash 时只需要看 hash 的某一位是 0 还是 1，即可确定新位置（原下标 + oldCap），不需要重新计算 hash。

5.1.5 为什么容量必须是 2 的幂？

  1. 取模优化：hash % n → hash & (n - 1)，位运算比取模快 10 倍
  2. 扩容均匀：扩容时节点要么在原位置，要么在 原位置 + oldCap，分布更均匀

5.1.6 为什么树化阈值是 8？

源码注释说明：在随机 hash下，链表长度达到 8 的概率是 0.00000006，几乎不可能。因此选 8 是泊松分布的合理阈值，避免过早树化浪费空间。退链化阈值是 6（避免频繁树化/退链化）。

5.1.7 HashMap 的”三宗罪”

  1. 非线程安全：多线程并发 put 可能导致数据丢失
  2. JDK 7 扩容死循环：链表头插法 + 并发扩容 → 链表成环，CPU 100%（JDK 8 改为尾插法已修复，但仍有数据不一致问题）
  3. resize 阻塞：扩容时全表 rehash，高并发下卡顿明显

5.2 ConcurrentHashMap：高并发下的”扛把子”

5.2.1 JDK 7 vs JDK 8 实现对比

维度 JDK 7 JDK 8
数据结构 Segment[] + HashEntry[] Node[] + 链表/红黑树
锁机制 分段锁（ReentrantLock） CAS + synchronized
锁粒度 Segment 级别（默认 16 段） Node 节点级别（更细）
读操作 不需要加锁（volatile） 不需要加锁（volatile）
并发度 受 Segment 数量限制 理论无上限
扩容 Segment 内扩容 多线程协同扩容

5.2.2 JDK 8 核心源码：put

三个关键点：

  1. CAS + synchronized 组合：
    • 桶为空 → CAS 插入（无锁）
    • 桶不为空 → synchronized 锁桶头节点（更细粒度）
  2. volatile 保证可见性：tabAt / casTabAt 用 Unsafe 的 volatile 读 / CAS 操作
  3. 多线程协助扩容：helpTransfer 让空闲线程帮忙迁移数据

5.2.3 size() 的”baseCount + sumCount”算法

为什么不用 AtomicLong？ 高并发下 AtomicLong 单一变量 CAS 竞争激烈，CounterCell[] 通过分散热点到不同槽位提升并发度。LongAdder 正是这个思想。

5.2.4 为什么不允许 null key / null value？

“The main reason that nulls aren’t allowed in ConcurrentMaps is because they can’t be safely used in a concurrent context. The null check is done after the value is retrieved, so the null can’t be reliably used to indicate ‘no value’.”

简单说：在并发下，get(key) == null 无法区分”key 不存在”还是”value 是 null”，会引发歧义。

九、8 道高频面试题精讲

Q1：ArrayList vs LinkedList 性能对比？

答：

  • 随机访问：ArrayList O(1) > LinkedList O(n)
  • 末尾追加：两者都是 O(1)，但 ArrayList 略快（CPU 缓存友好）
  • 中间插入/删除：LinkedList 理论 O(1)，但需先遍历到指定位置 O(n)，常数项也较大
  • 内存占用：ArrayList 紧凑（连续内存），LinkedList 每个节点 24 字节额外开销

面试加分：现代 JVM 下，ArrayList 的 100 万级数据随机访问比 LinkedList 快 10 倍以上，只有极端头尾操作才用 LinkedList。

Q2：HashMap 底层原理？JDK 7 和 8 的区别？

答：

  • JDK 7：数组 + 链表，头插法，多线程并发扩容可能死循环
  • JDK 8：数组 + 链表 + 红黑树，尾插法，引入红黑树避免链表过长退化

细节：

  • 初始容量 16，扩容 2 倍
  • 树化阈值 8，退链化阈值 6（泊松分布考量）
  • 容量必须是 2 的幂（位运算优化）
  • 加载因子 0.75（时间空间平衡）

Q3：ConcurrentHashMap 怎么保证线程安全？JDK 8 用了什么锁？

答：

  • JDK 7：Segment 分段锁，默认 16 段，每段独立加锁
  • JDK 8：CAS + synchronized，锁粒度更细（桶节点级别）

读操作无锁的原因：Node.val 和 Node.next 用 volatile 修饰，保证可见性。

size 统计：baseCount + CounterCell[] 分散热点，类似 LongAdder。

Q4：什么是 fail-fast？什么是 fail-safe？

答：

  • fail-fast：集合在遍历过程中被修改，立即抛 ConcurrentModificationException，如 ArrayList、HashMap
  • fail-safe：在原集合的副本上遍历，修改不影响遍历，如 CopyOnWriteArrayList、ConcurrentHashMap

实现原理：modCount（修改计数器），迭代器每次 next 都会检查 expectedModCount == modCount。

Q5：HashMap 怎么计算 key 的下标？为什么用扰动函数？

答：

扰动函数目的：高 16 位异或低 16 位，让 hash 高位特征也参与运算，避免大量冲突（特别是容量较小时）。

Q6：为什么 ConcurrentHashMap 不允许 null key / null value？

答：并发下，get(key) == null 无法区分：

  • key 不存在
  • key 存在但 value 是 null

二义性会导致 containsKey 和 get 在并发下行为不可预测。Hashtable 之所以允许 null 是因为它是全表锁，没这个问题。

Q7：TreeMap 底层是什么？时间复杂度？

答：底层是 红黑树（一种自平衡二叉查找树）。

操作 时间复杂度
get O(log n)
put O(log n)
remove O(log n)
firstKey / lastKey O(log n)
subMap O(log n)

为什么用红黑树而不是 AVL？

  • AVL 严格平衡，查询快但插入删除旋转次数多
  • 红黑树近似平衡，查询稍慢但插入删除更快
  • 工业界大多数场景插入删除更多，红黑树更实用

Q8：HashSet 怎么保证元素唯一性？

答：HashSet 内部是 HashMap，元素作为 key，value 是固定 PRESENT。判断重复：

  1. 先比较 hashCode（O(1) 定位桶）
  2. 再比较 equals（确认真的相同）

equals 和 hashCode 约定：

  • equals 相等 → hashCode 必须相等
  • hashCode 相等 → equals 不一定相等（哈希冲突）

生产经验：自定义类作为 key 时，必须同时重写 equals 和 hashCode，否则会重复插入。

十、总结：集合框架选型速查表

场景 推荐 备选
顺序列表（单线程） ArrayList LinkedList（极少用）
并发列表 CopyOnWriteArrayList（读多写少） Collections.synchronizedList
快速去重 HashSet LinkedHashSet（保序）
排序去重 TreeSet -
单线程 Map HashMap LinkedHashMap / TreeMap
并发 Map ConcurrentHashMap ConcurrentSkipListMap（排序）
LRU 缓存 LinkedHashMap（accessOrder=true） Guava Cache / Caffeine
阻塞队列 ArrayBlockingQueue（有界） LinkedBlockingQueue
优先级队列 PriorityQueue PriorityBlockingQueue
不可变集合 List.of / Set.of / Map.of Collections.unmodifiableXxx

黄金法则：

  1. 80% 场景：ArrayList + HashMap + HashSet 就能搞定
  2. 并发场景：用 ConcurrentHashMap 而不是 Hashtable 或 Collections.synchronizedMap
  3. 不熟悉原理前：不要在多线程下用 HashMap / ArrayList / HashSet
  4. 追求极致：了解 HashMap 源码才能调优，JVM 调优文章里集合分配是常见调优点
